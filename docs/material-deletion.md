# 教学材料删除与人工验收

变更：`add-teaching-material-deletion`。教师在「知识库管理」或旧材料页每份文件的查看、下载旁点击「删除」，确认材料名称和影响后提交。学生没有删除入口；直接调用仍受后端教师、班级、首次改密和CSRF校验。

## 删除的含义

删除确认后，材料立即退出材料/知识库列表、三种检索和AI应用资料绑定，不能再次查看、下载、重建或重新绑定。系统随后清理原文件、MySQL全文/切片/索引任务及Qdrant向量，仅保留不含正文的删除记录；不提供恢复或回收站。资料不可用和底层资源清理完成是两个状态：202 `cleanup_pending`表示已停止使用、后台清理中；200 `deleted`表示清理已确认完成，重复DELETE不会重复登记任务。

历史回答正文保留；重新打开会话时，引用显示“材料已删除，原文与引用片段不可用”，不提供原文/片段入口。已经发送给模型或显示在其他页面的内容不能追溯撤回；旧页面点击来源或刷新后会得到明确失效提示。存续材料重建引起的旧切片失效，仍按原有规则回退到该材料原文，不误报材料删除。

## 更新部署

由部署者备份数据库与原文件后在Windows CMD执行，不删除卷、不重新索引既有资料：

```cmd
cd /d D:\PKU\Projects\campusclaw-111
docker compose up --build -d --wait
```

若原部署启用了MCP，保持原启动方式：

```cmd
docker compose --profile mcp up --build -d --wait
```

迁移增加材料删除状态、向量写入确认状态及唯一清理任务表，原数据默认存续。不要回退到忽略删除状态的旧版API，否则可能重新暴露删除记录。数据库、文件及索引备份必须配套处理。

## 清理故障

Qdrant离线、文件删除失败等会保留任务并自动重试，间隔逐步增加，最大300秒；重启后继续处理。材料保持不可用，原文件只从受控上传目录移除，其他班级和材料不受影响。删除不会发起Chat或Embedding。

运维可只读检查 `material_deletions` 的 `status`、`attempts`、`last_error_code` 和 `next_attempt`。`vector_cleanup_not_configured`需恢复正确Qdrant配置，依赖故障需检查本地Qdrant，文件故障需检查上传目录权限。不要把这些状态当作材料仍可使用。

极端情况：进程在向量写入中崩溃或Qdrant写入回执丢失，不能证明远端写入已结束。此时保留 `vector_write_unconfirmed`，持续执行清扫但不谎报完成；需要运维确认远端不存在未完成写入后再处置，不提供自动清除此保护标记的接口。普通收到完成回执的写入和明确拒绝的请求不进入此状态。此限制不影响资料立即撤回，也不会恢复检索资格。

## 人工验收步骤

请上传专门可删除的短测试资料，不要用仍需保留的真实教学文件。教师/学生分别使用普通窗口与无痕窗口。

| 操作 | 预期结果 |
| --- | --- |
| 教师查看正文、下载测试文件 | 内容和原始文件一致 |
| 将文件绑定到测试应用，产生一条带该文件引用的会话 | 回答和来源可恢复；此步骤若使用真实模型会消耗额度，可复用已有测试会话 |
| 教师点删除，再取消或按Escape | 无删除请求、材料保留 |
| 再点删除并确认 | 不可重复点击；提示已停止使用/后台清理；列表数量更新 |
| 刷新教师及学生材料页、应用资料绑定 | 文件不再可见，绑定移除，其他资料仍正常 |
| 用三种检索模式查询该材料的唯一标记 | 不返回已删材料；向量服务故障应显示故障，不能当作空命中 |
| 学生恢复此前引用会话 | 正文保留，对应编号显示“材料已删除”，不显示旧片段 |
| 在删除前保留旧引用页面，删除后点击来源 | 显示明确删除提示，不打开错误资料 |
| 尝试旧原文、下载、切片及重建URL | 本班410及material_deleted，外班404 |
| 学生检查材料行及直接请求删除 | 没有按钮；直接请求403 |
| 桌面与窄屏，长材料名和确认弹窗 | 名称按文本显示，按钮可见可操作，无横向溢出 |
