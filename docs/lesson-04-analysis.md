## 2. 这一课究竟在做什么

例如教师上传《课程考核说明.md》，其中写“期末项目占总成绩的40%”。第三课只能打开文件后人工寻找；第四课允许学生问“项目成绩占多少”，系统从本班讲义中找到对应段落，将它交给模型，回答“期末项目占40% [1]”，并展示材料标题、切片位置和摘录，让学生打开材料核对。

这是示意业务例子，不是现有材料内容或已经实现的结果。相同问题在B班必须只使用B班材料；如果本班没有依据，应返回固定的未找到提示，不借模型常识补答案。

| 能力 | 第三课现状 | 第四课新增 |
| --- | --- | --- |
| 身份与权限 | Session、师生角色、首次改密、班级边界 | 复用并覆盖新接口 |
| 材料 | 教师上传 txt/md，全文入 MySQL，原文件保存、查看和下载 | 保存后切片、嵌入、建立可检索索引 |
| 找资料 | 材料列表和人工读正文 | 关键字、向量和混合检索 |
| 出处 | 可以打开整份材料 | 每条命中带材料和切片位置、摘录 |
| 回答 | 没有模型调用 | 有依据时生成简短回答并关联引用 |
| 无依据与故障 | 上传及数据库错误反馈 | 区分正常无命中、索引失败和依赖故障 |

RAG 不是训练或微调：本课没有把讲义“训练进模型”，而是在每次问题到来时，把检索出的少量证据作为输入。检索结果可能漏掉正确资料，模型也可能误读证据；增加引用并不自动保证每个结论正确，仍需核查。

## 4. 核心概念与技术选型

### 4.1 Chunking：把整份材料变成可定位的证据单元

将整篇讲义直接嵌入，一个向量会混合课程目标、考核规则等不同主题；切得太短，又可能只剩“40%”，缺少“什么占40%”。切片是检索的最小单位，重叠让窗口边界附近的语义有机会保留完整。

教程策略（S2、S4）：

| 策略 | 具体规则 | 业务适用 |
| --- | --- | --- |
| auto | 最大800字，重叠80字；优先空行、换行、句号；请求里的额外长度和预处理参数不生效 | 普通讲义的默认选择，种子补索引也用它 |
| custom | 最大100–2000字，重叠0%–50%；按所选换行/空行/句号分隔，无断点时强制截断；可去URL/邮箱、折叠空白 | 教师按材料格式调整粒度 |
| hierarchy | 按 Markdown `#`、`##`、`###` 分章，标题留在本章，超长再按自动窗口处理 | 带标题的结构化讲义 |

原文件和 `knowledge_entries.body_text` 不应被预处理覆盖。移除链接、折叠空白只作用于切分输入；启用后偏移指向预处理文本，不能冒称原文件字符下标。折叠空白后换行可能消失，策略组合会影响结果。

**实施建议：** Go使用Unicode字符序列切分，不能按UTF-8字节截中文。正式设计需确定序号从0还是1开始、区间是否左闭右开、CRLF和标题边界如何计数，前后端统一；这些细则尚未取得教师spec确认。重叠也意味着不同命中可能重复一部分原文。

### 4.2 Embedding：把文本映射到同一个语义空间

嵌入服务输入一个切片或问题，返回固定长度的浮点数组。意思相近的文本通常向量更接近，所以“项目成绩占多少”和“期末项目权重”可能在原词不同的情况下匹配。

它不是加密、压缩备份或回答生成，不能从向量直接还原完整原文。入库和查询要使用兼容的模型、维度和处理方式；只保证维度相同仍不足以混用不同模型。更换模型通常要重建全部相关向量。

教程采用服务端课程网关的兼容 OpenAI `/embeddings` 接口，未在已读页面指定确切模型名、base URL、维度、额度和鉴权细节。正式实现前需核实课程网关实际支持项，不能照填猜测的模型或维度。

### 4.3 向量数据库与两库分工

MySQL继续是文本和业务关系的来源；新增 `knowledge_chunks` 保存切片正文、归属、序号和位置，并建立全文索引。Qdrant保存固定维度向量和标识，用于按相似度寻找候选。

教程指定 Qdrant 集合 `campusclaw_chunks`、余弦度量，point ID = `knowledge_chunks.id` = payload中的 `chunk_id`。payload仅含 `class_id`、`material_id`、`knowledge_entry_id`、`chunk_id`、`chunk_index`，不复制正文。

例如Qdrant命中point 123，Go拿123及当前班级去MySQL读取对应切片和材料标题。即使向量库返回其他班级或过期ID，回表条件也应使其不能变成可见文本。

### 4.4 三种检索模式

| 模式 | 实际过程 | 优点与限制 |
| --- | --- | --- |
| keyword | MySQL针对 `chunk_text` 做全文检索，按全文相关度排序 | 适合材料原词、术语；没有语义改写能力，不访问嵌入服务和Qdrant |
| vector | 问句嵌入 → Qdrant按班级检索 → 过滤余弦相似度低于0.35的候选 → MySQL回表 | 支持近义表达，但近邻未必是真正依据；0.35是教程基线，不是跨模型通用保证 |
| hybrid | 两路分别检索和过滤 → 对候选ID去重并RRF融合 → 回正文 | 同时利用原词与语义；不能把全文分和余弦分直接相加 |

中文全文索引采用 MySQL `FULLTEXT ... WITH PARSER ngram`，教程token长度为2。它以相邻字符片段辅助中文匹配，并不是引入一整套中文语义理解。具体关键词绝对分数过滤值未在教程中给出；需在设计/教师spec核对后确定，不能将RRF分数充当该阈值。

keyword搜索本身不调用任何模型；但如果调用的是 `/api/ask`，其检索固定用hybrid，有命中后还会调用生成模型。不要把“关键字搜索不调用模型”误读成“任何包含关键字命中的问答都不调用模型”。

### 4.5 RRF：合并名次而非原始分数

教程使用 `k=60`。对每个候选切片，将它在各路列表中的 `1/(60+rank)` 相加；未出现的一路贡献0。若名次从1起算，切片X在关键字第1、向量第3，则得 `1/61+1/63≈0.03227`；只在向量第1的切片Y得 `1/61≈0.01639`。

这让两路靠前的共同候选通常获益，但不是“只要两路都出现就永远第一”。它也不是相关性概率：一个无关段落即使在某一路排第一，也不因此变得可靠。因此必须先按各路绝对分数过滤，再融合。正式设计还需明确稳定的并列排序和截断顺序。

### 4.6 班级隔离：扩展第三课的可信身份边界

本项目Cookie只存随机Session ID；`auth`每次查 `sessions JOIN users JOIN classes`，将真实角色和班级写入上下文。课件“从会话取班级”可以自然映射为 `currentUser(r).ClassID`，无需把班级写进Cookie或另造身份机制。

- 关键字SQL：同一可信 `class_id`，且只检索 `index_status=ready` 的切片。
- Qdrant：查询时携带同一个 `class_id` 过滤，不先全库取top-k再由前端筛选。
- 回表：再次限定班级，并校验可检索状态和材料关联。
- 提示输入、结果摘录和出处：只来自通过上述校验的本班文本。
- 客户端JSON、query或header里的班级不得决定范围。依教程应忽略其班级值；不能复用账号变更的严格未知字段逻辑而误伤伪造班级验收场景。

跨班专属内容的搜索应表现为正常200空结果；不能返回“你无权查看B班材料”泄露存在性。按ID打开跨班材料仍复用现有404。未登录401、学生写操作403与搜索空结果是不同情形。

### 4.7 来源溯源与生成

命中至少返回材料标题、切片序号、字符区间、摘录，并能打开对应材料；摘录来自MySQL `chunk_text`。来源不是模型随意写出的文件名，而是后端从已验证记录构造的引用列表。

问答使用本轮最新一句做本班hybrid检索，取前4条；将材料标题、切片序号和正文编号后交给生成模块。回答的 `[1]`、`[2]` 应与返回的 `citations` 顺序对应。没有候选时返回“资料中未找到相关内容”，空引用，**不调用对话网关**。

教程允许附带此前若干轮历史，丢弃客户端system消息，服务端构造系统提示；本课不做流式。历史条数、长度、角色白名单、生成错误及无效引用的具体处理尚需设计，不应伪称课件给出了所有数值。

实施建议：校验引用编号是否落在已提供证据集合内，材料与模型文本安全渲染；不要用模型输出直接拼HTML。材料中夹带的指令应视作资料内容，不能获得服务端提示的权限。这是落实可信回答的建议，不额外扩成安全平台作业。

```text
浏览器（现有原生HTML/CSS/JS）
  → Nginx（同源 /api，现有Cookie）
    → Go auth（现有Session、首次改密、可信用户/角色/班级）
      ├─ 材料模块（现有）：校验 → 保存原文件 → materials + knowledge_entries提交

      │         └─ 失败：保留原材料/正文，记录索引失败，不伪装ready
      ├─ search（新增）：keyword / vector / hybrid
      │    ├─ MySQL全文索引（本班、ready）
      │    ├─ 问句嵌入 → Qdrant（本班、相似度过滤）
      │    └─ 过滤/融合 → MySQL本班回表 → hits + 可打开的来源
      └─ ask（新增）：hybrid前4条
           ├─ 空：固定文案 + 空citations，不调用生成
           └─ 有：编号证据 + 最新问题 + 受限历史 → 对话网关 → answer + citations
```

关键边界：嵌入网关将文本变为向量；生成网关依据文本作答；Qdrant找候选；MySQL提供正文；Go负责授权与编排。浏览器始终只访问本站，不拿模型密钥，也不直连Qdrant。检索页不展示向量分量；S7提到的 `query_vector` 等字段可用于观察网络行为，不等于要在产品界面暴露数组。

## 6. 基础环境、兼容性与风险

### 6.1 当前具备什么

项目已有Go模块、标准库HTTP服务、MySQL8.4、Nginx、Docker Compose、原生静态前端及独立测试模式；本机可发现Docker和OpenSpec命令，项目 `.local/tools/go/bin/go.exe` 与既有jsdom依赖存在。因此有直接扩展的代码和工具基础，无需重新搭后端。

但Compose仅定义web/api/db，schema没有切片表或FULLTEXT，配置没有网关/Qdrant项，路由没有search/ask/reindex；源码搜索也未发现检索实现。尚不能说“RAG环境已经就绪”。网关权限/模型/额度、真实维度、Qdrant可用性、ngram运行配置均未验证；文件存在也不等于工具或服务本轮运行通过。

`git remote -v`当前无输出，项目文件在本次状态中均为未跟踪；不能据本地文件判断已提交远程仓库。作业截图明确要求开放仓库地址，用户明确自行处理仓库与提交；本轮仅完成本地材料，不初始化、提交或推送。

### 6.2 必须在设计阶段解决的兼容点

1. **主规格中的旧限制。** `teaching-materials/spec.md`明确要求入库不调用模型/向量；`AGENTS.md`也将txt/md限定为第三课全文保存。第四课需要在获批后明确修订当前限制，保留“文件/全文先提交”的语义；不能默默接外部调用，却声称旧规格无需变化。当前归档设计作为历史保留，不回写重塑第三课范围。
2. **上传互斥与事务时长。** `upload`持有 `uploadMu` 到函数结束，全文落库事务后返回201。不要在持锁或数据库事务中做整批网络嵌入，长文件可能阻塞其他教师。建议提交之后交给可恢复的索引步骤，或采用有界同步索引并释放原锁；同步/后台的取舍须先设计。第八课才讲消息队列，本课不必引入Redis或队列平台。
3. **双库没有共同事务。** Qdrant写失败/超时与MySQL提交结果不确定会产生部分索引。至少需状态、幂等写入、失败可重试、回表过滤及旧向量清理；不能宣称靠一个SQL事务实现两库原子性。
4. **重建和并发。** 教程要求删除旧切片与旧向量再按本次策略重建，期间可能暂时无结果；旧ID也可能仍被向量库返回。需串行化同材料的重建、校验删除/写入状态，并明示失败状态。影子索引无缝切换是可选增强，不是最小作业范围。
5. **ready与关键词可用性。** 教程关键词只查ready。嵌入失败形成failed切片，即使有文字也不会被搜出；已有ready索引在Qdrant故障时仍可单独keyword搜索。两种情况要分开解释。
6. **中文全文索引。** MySQL版本路线相容，但需验证ngram解析器、token长度、停用词和实际中文查询；不能用LIKE伪装全文检索，也不能假设创建表便已满足运行参数。若需改启动参数，由用户后续执行容器重建，不在本轮操作。
7. **时间和容量。** Go服务读写超时与Nginx代理读超时当前均有30秒限制；5MiB正文切成数千片时，逐片外呼可能远超时间和额度。需有界批处理、并发/重试预算、前端索引状态。具体上限与网关能力确认后再定，不能无限放宽超时掩盖问题。
8. **模型与集合。** 维度错误应明确失败，不能填零向量或随机数使流程看似通过；模型切换必须考虑旧索引。网络不可用、认证错误和限额应区别于200无命中。
9. **健康与降级。** 教程要求Qdrant不可用时keyword仍可用，vector/hybrid返回503。若Qdrant故障直接使Go全局健康失败、Nginx拒绝转发，可能连keyword也不可用。建议保留第三课基础健康，另表达检索依赖状态，并避免对Qdrant设置阻断整站启动的硬依赖；细节待设计。
10. **历史材料补索引。** 当前已有用户材料和种子全文，不能只索引新上传文件，也不能重新Seed重置账号。教程明确种子自动默认策略补索引；对既有非种子材料建议通过教师显式重建/受控批处理补齐，过程幂等且保留原数据。
11. **新增输入边界。** 当前JSON帮助函数限制16KiB，适用于登录，不一定适合历史问答。需要为q/history设计合理界限，保留认证与CSRF，拒绝不合法模式/参数。客户端班级无效与客户端system丢弃也要有可测契约。
12. **出处与安全展示。** 原生前端适合直接扩展，但要处理预处理坐标、Unicode、重建后旧引用和模型格式。打开整份正文可复用；原文精确高亮需要额外坐标映射，不能假装偏移天然匹配。

总体判断：课程方案与当前Go/MySQL/Nginx架构高度适配。真正难点是已有数据、索引状态、双库失败和授权链路，而不是替换技术栈。
