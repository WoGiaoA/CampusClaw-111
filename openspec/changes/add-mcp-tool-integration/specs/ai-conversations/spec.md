# AI 会话增量

## MODIFIED Requirements

### Requirement: 真实 SSE 与持久化边界

新消息接口 MUST 从上游真实增量推送 meta、delta 和单一终止事件。有工具意图时 MUST 在最终正文前推送工具状态。成功 MUST 先原子保存助手正文、技能与引用，再发 done。流内失败 MUST 发 error（连接仍可写时），并保留已接受的用户问题及失败状态。

#### Scenario: 多增量与成功回放
- **WHEN** 上游分时返回多段正文并正常结束
- **THEN** 浏览器在上游结束前看到增量，按序拼接 delta 等于回放中的正文，done 携带已提交的助手消息 ID

#### Scenario: 断流、超时、取消或保存失败
- **WHEN** 已接受的请求在成功提交之前发生超时、主动取消、无有效结束标记或保存失败
- **THEN** 回放没有部分助手消息和已完成引用，用户消息标为未完成或失败；若仅 done 丢失，重新读取可获得已提交结果

#### Scenario: 先工具进度，再最终正文
- **WHEN** 模型提出多个分片工具调用，执行成功或返回受控拒绝后生成正文
- **THEN** 已发送的 meta 保持有效，工具状态早于首个 delta；仅最终正文的增量参与保存，恢复本人会话可见已记录的工具摘要

## ADDED Requirements

### Requirement: 有限工具循环及结果回传

宿主 MUST 在有候选时声明工具并聚合完整调用，复核后执行。后续模型请求 MUST 带对应 assistant 调用和 tool_call_id 匹配的 tool 结果。达到轮次或会话限额 MUST 停止执行并转入无工具收尾。没有可用候选的普通会话 MUST 保持第 5 课路径。

#### Scenario: 两步工具调用及限制
- **WHEN** 模型先请求公式提示，再用结果的策略键请求后续提示，另用接近会话限额的对照请求触发超额
- **THEN** 独立工具的实际结果可关联到各自模型 ID；超额请求未派发，后续请求不声明工具，模型可用已知信息收尾

#### Scenario: 无候选或不可恢复的协议错误
- **WHEN** 未绑定工具、模型直接回答，或工具调用片段缺失或无法关联
- **THEN** 无候选时不发送工具声明，直接回答正常流式输出；不可恢复的协议错误不执行工具，按 SSE 失败边界处理


### Requirement: 无工具约束与协议文本保护

系统 MUST 在无可用工具及工具收尾阶段明确禁止模拟调用，正文流 MUST 拦截内部工具调用标记，不将其当成执行或成功答案。

#### Scenario: 撤权后普通引导
- **WHEN** Skill仍声明工具但应用已撤销授权
- **THEN** 出站请求不包含tools并附当前无工具约束，可正常以文字回答，不能新增工具调用或审计记录

#### Scenario: 标记分片与异常回答
- **WHEN** 模型在content中输出完整、跨增量分片或截断的工具协议标记
- **THEN** 标记不出现在学生增量或成功历史，返回可读unexpected_tool_text错误，无自动重试，无文本转执行；已有历史只在显示时隐藏同类内容并保留原数据
