# 工具审计与验收

## Purpose

让教师核对本班工具执行与拒绝记录，并将真实本地工具、模型替身和后续真实网关证据分开，支持可复验的课程和阶段验收。

## ADDED Requirements

### Requirement: 追加式调用审计

系统 MUST 追加记录可归属的工具尝试与结果，包括班级、用户、会话、轮次、服务/工具、时间、状态、原因和脱敏摘要。审计不得修改既有事件。教师 MUST 仅能分页读取本班记录，学生仅能在本人会话看到有限过程摘要。

#### Scenario: 成功、拒绝、失败与恢复
- **WHEN** 工具成功、断开后被拒、超时，或进程在已记录派发后退出
- **THEN** 本班教师可关联记录及终态，失败原因安全可读；启动恢复追加中断事件，同伴班级和学生均无法读教师审计

### Requirement: 本地接口试调和两跳取证

系统 MUST 扩展同源 Swagger、OpenAPI 和 apitest runner，记录经真实本地 MCP 的握手、发现、执行及结果回传。测试默认只用本地模型替身，证据 MUST 区分替身与真实课程网关。

#### Scenario: 零额度验收
- **WHEN** 使用合成资料、隔离库、真实本地 MCP 和脚本化 Mock LLM 运行完整测试
- **THEN** 可核对有无候选时的出站字段、调用 ID 对应、工具结果改变最终回答、断开/限额拒绝和审计；生成本地 HTML，真实 Chat 与 Embedding 请求数均为零
