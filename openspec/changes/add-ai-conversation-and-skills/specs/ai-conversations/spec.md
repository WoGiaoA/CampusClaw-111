# AI 会话增量

## Purpose

让学生恢复本人在班级应用中的连续对话，用有界历史和获准的知识片段形成模型上下文，并以可验证的流式事件呈现真实生成过程及保存结果。

## ADDED Requirements

### Requirement: 会话归属与应用锁定

系统 MUST 允许学生用本班启用应用创建会话、分页查询并恢复本人历史。应用在创建时固定。会话所有权和当前班级 MUST 由服务端验证。已有会话在应用停用后仍可继续，之后每轮读取最新角色、模板、绑定和 Skill 状态。

#### Scenario: 跨用户、跨班与停用
- **WHEN** 他人、他班学生访问会话，或学生选择停用应用创建会话
- **THEN** 返回与资源不存在相同的 404；原所有者仍可进入此前已创建会话，且发送接口不接受替换应用的字段

### Requirement: 限量历史与单次当前问题

每轮模型消息 MUST 使用有效 system、按时间正序的近期历史、当前 user 消息。窗口最多 6 条，包含当前提问，每条历史正文最多 500 个 Unicode 码点。当前问题 MUST 仅作为本轮 user 消息正文出现一次。

#### Scenario: 长历史与失败轮
- **WHEN** 已有超窗历史、超过 500 码点的正文和失败轮，并提交追问
- **THEN** 仅取最近最多 5 条非空已完成 user/assistant 消息，逐条截断后按时序发送；失败轮与历史引用附件不进入请求，本轮问题和本轮证据一起构成最后一条 user 消息

### Requirement: 绑定范围内的证据检索

系统 MUST 在候选排序和截取前限制两路检索的班级和应用材料集合，并在 SQL 回表复核同班、绑定、索引代次和 ready 状态。模型 MUST 只接收本轮命中的至多四条编号片段。

#### Scenario: 对照与可回查来源
- **WHEN** 同班绑定、同班未绑定及跨班材料各有高相关片段，或向量服务返回越界候选
- **THEN** 未授权候选不可入模或出现在引用中；真实引用可定位到同班原文与切片区间，历史引用反映当轮证据且回查仍验证当前权限

#### Scenario: 无资料、无命中与故障
- **WHEN** 未绑定资料、已绑定但无命中或检索依赖故障
- **THEN** 分别标识 unbound、no_hits 或明确检索失败。前两者继续按角色生成且没有引用，未绑定时跳过检索和 Embedding；故障不调用 Chat。原单轮 ask 保留无命中不生成及既有接口语义

### Requirement: 真实 SSE 与持久化边界

新消息接口 MUST 从上游真实增量逐帧推送 meta、delta 和单一终止事件。成功时 MUST 先原子保存助手正文、命中技能与引用，再发 done。流内失败 MUST 发 error（连接仍可写时），并保留已接受的用户问题及失败状态。

#### Scenario: 多增量与成功回放
- **WHEN** 上游分时返回多段正文并正常结束
- **THEN** 浏览器在上游结束前看到增量，按序拼接 delta 等于回放中的正文，done 携带已提交的助手消息 ID

#### Scenario: 断流、超时、取消或保存失败
- **WHEN** 已接受的请求在成功提交之前发生超时、主动取消、无有效结束标记或保存失败
- **THEN** 回放没有部分助手消息和已完成引用，用户消息标为未完成或失败；若仅 done 丢失，重新读取可获得已提交结果

### Requirement: 重复提交与同会话并发

系统 MUST 按会话和客户端请求 ID 去重，同会话仅允许一轮生成。拒绝的并发、重复或冲突请求不得新增用户消息或发起额外模型调用。

#### Scenario: 并发及恢复
- **WHEN** 重复发送同一请求 ID、用同 ID 更换正文，或另一个 ID 在活动轮次期间提交
- **THEN** 返回 409 及可恢复状态；活动轮次终止后允许用新 ID 显式重试，进程重启后遗留活动轮次可恢复为失败
